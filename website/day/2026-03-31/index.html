Day in brief

Linux broker guidance flags new Intune and Entra device IDs after upgrades

31 March combined a significant Linux identity-transition note with several precise Intune guidance changes. The Linux enrollment guide documents automatic re-registration and re-enrollment when Identity Broker 2.0.2 or later updates, creating new Intune and Microsoft Entra device IDs. Intune now lists RHEL 9 and 10 LTS as supported while RHEL 8 support has ended; expedite guidance covers security and non-security updates; and macOS LAPS is tied to post-reset ADE. Security Copilot material lists four Intune agents, but the move from /agents to /copilot/agents is documentation reorganization rather than evidence of retirement or GA. Vulnerability Remediation remains limited public preview. The filters matrix also marks Antivirus, Disk encryption, and Firewall as supported workloads.

  • Intune · Device enrollment
    Linux broker migration guidance documents automatic re-enrollment

    The Linux enrollment guide adds that Microsoft Identity Broker 2.0.2 and later, included with the Microsoft Intune app for Linux, introduces a major architectural change. When devices update from earlier broker versions, Intune automatically re-registers and re-enrolls them and creates new Intune device IDs and Microsoft Entra device IDs. The documented behavior requires no user action.

  • Intune · Fundamentals
    RHEL 8 support ends while RHEL 9 and 10 remain supported

    The Intune What's New guidance states that RHEL 9 LTS and RHEL 10 LTS are supported, while support for RHEL 8 LTS has ended. Devices already enrolled on RHEL 8 remain enrolled. Administrators can find them under Devices > All devices by filtering OS to Linux and adding OS version columns, then notify users to upgrade.

  • Intune · Endpoint analytics
    Expedite guidance adds non-security updates and Windows 11 caveats

    The Expedite Policies article now describes accelerating specific Windows security and non-security updates, rather than security updates alone. It says existing settings don't have to be modified but recommends configurations that avoid conflicts, including Automatic update behavior set to Reset to default; settings that prevent scanning can block the expedited scan, and download approval can delay updates.   • Intune · Device enrollment
    macOS LAPS guidance adds a post-reset ADE prerequisite

    The macOS LAPS article now specifies that the feature is enabled during automated device enrollment only after a factory reset. Previously enrolled devices must reenroll with Intune using a LAPS-enabled ADE profile after the reset. ADE enrollments initiated from terminal Sudo profiles renew aren't supported.

  • Security Copilot · Fundamentals
    Vulnerability Remediation Agent remains limited public preview

    New setup material explicitly says the Vulnerability Remediation Agent is in limited public preview and available only to a select group of customers; interested organizations should contact their sales team. The agent uses Microsoft Defender Vulnerability Management data to identify CVEs, prioritize remediation, and provide step-by-step Intune guidance. The material describes a preview capability, not general availability.
