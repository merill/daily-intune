Checklist for 2609 - Configuration Manager | Microsoft Learn

6 November 2026Feature updateAction required+17 / −4 lines

In brief

The checklist now states that version 2609 automatically disables shared-key access for CMG storage and adds prerequisites for existing CMGs, including service-principal role-assignment permissions and Microsoft.Maintenance registration.

What Intune admins need to know

Before updating, verify permissions and provider registration, allow changes to propagate, and validate CMG deployment and client communication afterward. Missing prerequisites can cause the update to fail.

Verify Azure prerequisites for existing CMGs

If your hierarchy uses a cloud management gateway (CMG), verify its Azure prerequisites before updating the site. Version 2609 automatically disables shared-key access for CMG storage, including deployments where you haven't previously selected that option.

  • Verify that the CMG server/web application's service principal has the required resource-management and storage role-assignment permissions at the CMG resource group. Contributor alone doesn't grant permission to create role assignments. Use appropriately constrained permissions as described in Configure Azure RBAC permissions for the server app.
  • Verify that Microsoft.Maintenance is registered in every subscription containing a CMG, along with the other required resource providers. Wait until registration is complete.
  • Allow time for permission changes to propagate, then verify the effective access for each CMG server application and resource group. Check production separately from staging: role assignments are scoped to Azure resources, and provider registration is subscription-scoped. Neither change is tenant-wide.

These prerequisites apply to existing deployments even if earlier CMG updates succeeded. Missing permissions or registration can cause the CMG deployment update to fail. For error details, review CloudMgr.log and the failed Azure deployment operations.

Review the site and hierarchy status for unresolved issues

A site update can fail because of existing operational problems. Before you update a site, resolve all operational issues for the following systems:

Consider restarting remote site systems that don't successfully update at first. Review your site infrastructure and make sure that applicable site servers and remote site system servers successfully restarted. Typically, site servers restart only when Configuration Manager installs .NET as a prerequisite for a site system role.

Verify CMG deployment and client communication

After updating a site that has a CMG, verify that the CMG deployment update completes successfully. Review CloudMgr.log and any failed Azure deployment operations. After the CMG is running, use the CMG connection analyzer to verify communication.

Review SQL Server client components

Starting in version 2609, Configuration Manager automatically installs Microsoft OLE DB Driver for SQL Server on site servers and on computers that host the SMS Provider or a management point. SQL Server Native Client is no longer required. For more information, see Site and site system prerequisites.
