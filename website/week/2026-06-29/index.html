Week in brief

Security Copilot agent guidance adds an Intune RBAC permission-delay warning

The supplied period is dominated by documentation maintenance rather than evidenced product rollouts: many representative edits change collection metadata, author fields, or typography. Two substantive documentation changes stand out. Security Copilot guidance now calls out RBAC permission propagation for the Vulnerability Remediation Agent, while Intune’s third-party compliance partner page replaces Kandji with Iru. Neither diff, by itself, establishes a product retirement or tenant behavior change.

  • Security Copilot · Troubleshooting
    Vulnerability Remediation Agent guidance adds an RBAC propagation warning

    The Security Copilot Vulnerability Remediation Agent page now adds an IMPORTANT note that permissions assigned through an Intune RBAC role may take several minutes to take effect after the agentic user is added to the group. This is operational troubleshooting guidance, not evidence of a new agent capability.

  • Intune · Device security
    Intune’s third-party compliance list replaces Kandji with Iru

    The Third Party Partners page removes the Kandji entry and its Kandji Device Compliance link, replacing them with an Iru link for Microsoft Device Compliance getting started guidance. The change establishes a documentation listing change, but does not establish a Kandji retirement or a change in tenant support.

For Intune administrators

Allow several minutes for Intune RBAC permissions to take effect after adding the Vulnerability Remediation Agent’s agentic user to a group before troubleshooting access. For third-party compliance integrations, review internal references to the partner list, but do not infer from this documentation diff alone that Kandji support was retired or that Iru availability changed in the service.
