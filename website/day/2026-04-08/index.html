Intune adds security-task and Android migration guidance amid documentation restructuring

On 8 April, the most operationally relevant additions were new guidance for Intune security tasks with Defender Vulnerability Management, Android device-administrator migrations, and Apple automated device enrollment authentication. These are Microsoft Learn documentation additions—not evidence of a new preview, general-availability launch, or changed service behavior. The broader set is dominated by page moves, link and image-path corrections, and paired additions and removals; the older vulnerability article now appears under a new filename, and no Message Center item is supplied.

  • Intune · Device security
    Defender vulnerability guidance connects scans to Intune security tasks

    The new how-to documents the integration prerequisites: Intune Plan 1 and Defender for Endpoint, a service-to-service connection with the Microsoft Intune connection enabled in the Defender portal, and device onboarding with risk assessment enabled. Security admins create remediation tasks in Defender, while Intune admins act on them in the Intune admin center; only compatible vulnerabilities generate tasks, which include type, priority, status, and remediation steps. This is security guidance, not a stated feature

Users can then select **Resolve** and follow a checklist to unenroll from device administrator management, enroll a personally owned work profile, and resolve compliance issues.     Android MAM guidance offers a no-enrollment path away from device administrator

    A separate migration guide positions mobile application management without device enrollment for personal devices where full MDM controls such as Wi-Fi or email configuration are not needed. It lists the required Managed apps permissions—Assign, Create, Delete, Read, Update, and Wipe—and identifies the built-in Application Manager role as sufficient. The Company Portal app is required so users can receive app protection policies; the article documents a migration approach rather than announcing new MAM availability
