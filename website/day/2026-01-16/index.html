Day in brief

“Deny access to this computer from the network” blocks local Autopilot Reset

16 January was a documentation-maintenance day rather than a product-release day: all 27 supplied changes were updates, with no new, removed, or Message Center items. The standout was a newly added Windows Autopilot known-issue entry documenting that a specific local-account denial setting prevents local Autopilot Reset. Other meaningful edits clarify Microsoft Edge policy-conflict scope, Azure Monitor reporting latency, and which Windows update policies control client-side behavior. Nothing supplied establishes a new feature, preview, general availability release, retirement, or changed service behavior.

  • Windows Autopilot · Device enrollment
    Local Autopilot Reset has a newly documented local-administrator failure mode

    Windows Autopilot documentation adds a known issue dated January 16, 2026: when an Intune policy sets “Deny access to this computer from the network” for the Local account, a local Windows administrator cannot initiate local Windows Autopilot Reset. The issue is under investigation; the documented workaround is to remove the setting or exclude affected devices.

  • Intune · App management
    The Edge policy-conflict warning is now explicitly scoped to Microsoft Edge

    The Mamedge Settings Catalog guidance changes the warning from a broad statement about App Configuration Policies and Settings Catalog policies to one covering policies targeting Microsoft Edge. Administrators should still avoid deploying both policy types to the same client for Edge; the edit is a documentation clarification, not evidence of a policy-engine change.

  • Intune · Endpoint analytics
    Azure Monitor guidance clarifies the full Intune log-delivery window

    The Review Logs Using Azure Monitor article now states that Device Compliance Organizational Logs and Intune Devices report data is sent once every 24 hours, at any time during that period. It can therefore take up to an additional 24 hours to reach Azure Monitor, after which it typically appears within 30 minutes. This clarifies reporting expectations rather than announcing a telemetry change.

  • Intune · Device updates
    Quality update guidance separates targeting from client-side update controls

    Intune’s quality update guidance now explicitly assigns restart settings, deadlines, notifications, and deferral periods to update rings and Windows Update client policies. Quality update policies remain the surface for targeting quality updates and scenarios such as expedited updates and hotpatch. The change clarifies administrative boundaries rather than launching a capability.
