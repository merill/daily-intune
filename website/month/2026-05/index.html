Month in brief

Cloud PKI documents staged CA renewal while Intune warns against trusting device-reported values

May was heavily maintenance-oriented, with 968 updates among 1,014 entries, but several diffs have concrete administrator relevance. A new Cloud PKI article documents staged certificate-authority renewal; Intune compliance reporting adds explicit warnings about unvalidated device-reported values; custom-compliance guidance replaces Red Hat Enterprise Linux 8 with 10 on one supported-platform listing; Security Copilot documents delegated permissions for the Vulnerability Remediation Agent; and Windows Autopilot guidance removes the preview label while adopting Windows 365 Flex terminology. Most items are documentation or security-guidance changes. The Autopilot edit is an availability signal, not supplied proof of general availability, and the evidence does not establish a broad retirement or tenant-wide enforcement change.

  • Cloud PKI · General
    Cloud PKI adds documented staged certificate-authority renewal

    A new Cloud PKI article describes renewal for Intune-managed and bring-your-own-CA issuing CAs. Renewal always creates a new public/private key pair, preserves access to certificates and CRLs from earlier CA versions, and can be performed through the Intune admin center or Microsoft Graph. A CA becomes eligible at half its validity lifetime or after expiration; renewal creates a staged CA that must be activated, and expired CAs cannot issue certificates until activation.   • Security Copilot · Fundamentals
    Vulnerability Remediation Agent guidance defines delegated run permissions

    The updated Security Copilot guidance says the agentic user needs delegated permissions assigned outside the Intune admin center, in Microsoft Entra and Microsoft Defender. In Intune, the documented option is Read Only Operator or a custom role with Mobile apps/read and Device configurations/read; the Defender requirement is a granular custom RBAC role equivalent to Unified RBAC Security Reader. The same Intune permissions are listed for viewing results.

  • Intune · Device security
    Compliance reports now warn that Setting values are unvalidated device output

    A new compliance-reporting section describes a Setting value column that can show information reported directly by a device, application, or administrator-supplied script. Intune does not validate or enforce the content, which may include free-form text, URLs, or file paths. The guidance says to use these values only for context, not as the sole basis for administrative action, and to independently verify links or files before opening them.

  • Intune · Device security
    Custom-compliance guidance replaces RHEL 8 with RHEL 10 in its platform list

    The custom-compliance documentation changes the listed Red Hat Enterprise Linux version from 8 to 10. It also reiterates that administrators must prepare a JSON file and discovery script, upload the script before creating the compliance policy, and select that script when configuring the policy. This is a documentation scope and procedure change; the supplied diff alone does not prove that a service-side support retirement occurred.

  • Windows Autopilot · Device enrollment
    Windows Autopilot automatic mode guidance drops its preview label

    The Windows 365 automatic-mode article removes “preview” from its title, description, headings, and public-preview note. It also replaces Windows 365 Frontline with Windows 365 Flex for shared and dedicated scenarios and related links. The change signals updated availability and terminology guidance, but the supplied evidence does not establish general availability.

For Intune administrators

Cloud PKI administrators should review renewal permissions, eligibility, staged activation, and the impact of expired CAs before certificate issuance is at risk. Update compliance-reporting runbooks so Setting values are treated as untrusted context rather than enforcement evidence. Revalidate custom-compliance rollout assumptions for RHEL 8 and RHEL 10, audit the Vulnerability Remediation Agent’s delegated Intune and Defender permissions, and update internal Windows 365 references from Frontline to Flex while confirming current Autopilot availability before rollout. The single Message Center item provides no feature-level detail that warrants additional action.
