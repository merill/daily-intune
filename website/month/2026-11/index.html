Month in brief

Device-targeted scripts and policy-level security reporting lead November Intune updates

November was documentation-led: all 18 supplied entries were updates, with no new or removed items and no Message Center notices. The most consequential guidance changes cover PowerShell assignment on Azure Virtual Desktop multi-session, security-policy reporting, Win32 app delivery allowlists, and co-management enrollment troubleshooting. Most other edits involved wording, links, dates, navigation, or reference maintenance.

  • Intune · General
    Azure Virtual Desktop multi-session scripts now require device targeting

    Updated Intune guidance requires PowerShell scripts to be targeted to devices. It specifies No for logged-on credentials when system context is needed and Yes for user context. Review affected assignments and change user-targeted scripts to device targeting where necessary.

  • Intune · Device security
    Device-assigned PowerShell scripts are documented to run for every new user

    The Windows PowerShell script guidance now states that a script assigned to a device runs for every new user who signs in, removing the previous multi-session SKU exception. Use this behavior when planning scripts for multi-session devices.

  • Intune · Device security
    MDM Firewall and ASR policies report only at policy level

    Security Settings Management guidance now states that per-setting reporting is unavailable for Firewall Rules and ASR Rules policies managed through MDM. Administrators should use policy-level status when reviewing these policies.

  • Intune · Fundamentals
    Win32 app delivery allowlists gain two MEM-Win32Apps hostnames

    The Intune endpoint list now includes mmcswdc01.blob.core.windows.net and mmcswdc02.blob.core.windows.net for MEM-Win32Apps, alongside the existing hosts. Add them to network allowlists where required.

  • Configuration Manager · Device enrollment
    Co-management enrollment troubleshooting adds Windows version and log checks

    Configuration Manager guidance now states that device-token auto-enrollment requires Windows 10 version 1803 or later, falls back to the user token if the device token fails, and directs troubleshooting to ComanagementHandler.log. Check the Windows version and log when enrollment is pending or fails.

For Intune administrators

Review Azure Virtual Desktop multi-session PowerShell assignments: target scripts to devices and set logged-on credentials to No for system context or Yes for user context. Use policy-level status for MDM-managed Firewall Rules and ASR Rules. Add the two listed MEM-Win32Apps hostnames to network allowlists where explicit allowlisting is required. For co-management enrollment issues, verify Windows 10 version 1803 or later and check ComanagementHandler.log.
