Week in brief

OpenClaw baseline reference warns Node.js and WSL controls may disrupt workloads

The week was mostly documentation maintenance, but several changes have direct planning value. The Intune security-baseline overview now lists Local AI Agent Baseline - OpenClaw as a Preview, while its new settings reference documents outbound Node.js/runtime controls and warns they may disrupt legitimate processes. Security Copilot’s Vulnerability Remediation Agent guidance changes from limited public preview for selected customers to public preview. New Intune licensing and account-move references clarify plan structure and regional data-at-rest moves; custom-compliance guidance now lists RedHat Enterprise Linux 10 rather than 8 and makes discovery-script sequencing explicit. Separately, iOS/iPadOS compliance references now say iOS 17.0 and later rather than iOS 8.0 and later for multiple settings. The removed Create App Based Policy page is a documentation retirement, not evidence that app-based Conditional Access was retired; much of the remaining work is terminology, link, and prerequisite-layout cleanup.

  • Intune · Device security
    OpenClaw reference documents runtime controls and a deployment warning

    The new Intune settings reference says the baseline limits unauthorized local AI agents by disrupting common execution paths. It includes firewall rules that restrict outbound communication from runtime environments such as Node.js, plus controls that can affect Windows Subsystem for Linux and Node.js. The reference warns that the baseline may not block every execution path and may block other processes, so each setting should be reviewed and tested; it also points admins to Properties catalog inventory for Local ‌

  • Security Copilot · Fundamentals
    Vulnerability Remediation Agent guidance changes from limited to public preview

    The setup article replaces wording that the feature was in limited public preview and available only to a select group of customers with a statement that it is in public preview, linking to Public preview in Microsoft Intune. This is a documented preview-status change, not a general-availability announcement or proof that every tenant has access.

  • Intune · Fundamentals
    New licensing reference maps Intune Plan 1, Plan 2, and Suite

    The new Microsoft Intune licensing article defines Plan 1 as the base service, Plan 2 as additive to Plan 1 with advanced capabilities including Remote Help and Advanced Analytics, and the Intune Suite as additive to Plan 1 and including Plan 2. It also states that users or devices benefiting directly or indirectly from Intune need an Intune license and documents a device-only subscription. This is a new reference and does not by itself show that entitlements changed.

  • Intune · Fundamentals
    Account-move guidance separates regional data moves from tenant migration

    The new overview says an Intune account move relocates customer data at rest between geographic datacenter regions while preserving the tenant, policies, profiles, device enrollments, app-management state, and service configuration. It explicitly says the process is not a tenant-to-tenant migration, and distinguishes customer-requested moves coordinated through Microsoft support from Microsoft-initiated moves with advance notice. This is planning guidance, not evidence that a move is scheduled for a tenant.

  • Intune · Device security
    Custom-compliance guidance now lists RHEL 10 and script sequencing

    The custom-compliance guide changes its listed Linux distribution from RedHat Enterprise Linux 8 to RedHat Enterprise Linux 10. It also spells out that administrators must prepare a JSON file and discovery script, upload the script to the Microsoft Intune admin center before creating the policy, and use one script per compliance policy even though each script can discover multiple settings. This is a documentation update; the supplied diff does not prove that backend platform support changed.

For Intune administrators

Pilot and test the OpenClaw baseline, use the Properties catalog to inventory local AI agents, and review settings that could affect legitimate Node.js or Windows Subsystem for Linux workloads. Treat the Vulnerability Remediation Agent as public preview, not general availability. Use the new licensing and account-move references for entitlement and data-residency planning. Revalidate Linux and iOS compliance assumptions against the current references before changing policy guidance, because the supplied diffs alone do not establish a service-side enforcement change.
