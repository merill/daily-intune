Week in brief

Intune’s single-device page becomes default, replacing legacy view in September 2609

The period’s clearest operational change is Intune’s new single-device page becoming the default in the September (2609) release, replacing the legacy page while retaining all management features. Updated guidance also documents tenant-wide device-action quotas and clarifies easy-to-misread Defender Antivirus catch-up settings. Security Copilot’s Change Review Agent documentation now carries a deprecation notice, while Configuration Manager guidance improves MBAM migration group mapping.

  • Intune · Endpoint analytics
    The new single-device view becomes Intune’s default in September 2609

    The new Intune single device page will become the default in the September (2609) release and replace the legacy page. All management features remain available, but administrators should update internal documentation and familiarize themselves with the new interface beforehand.

  • Intune · Android
    Device-action documentation now lists cumulative tenant-wide daily quotas

    The updated Device Actions guidance lists daily limits of 500 Wipe actions and 1,000 each for Retire and Delete. Individual, bulk, and Microsoft Graph submissions count cumulatively toward the tenant-wide totals.

  • Intune · Device security
    Defender Antivirus guidance clarifies inverse catch-up scan settings

    Because the settings are named “Disable catch-up...”, Yes disables catch-up scans and No enables them. Full-scan catch-up is disabled when not configured, quick-scan catch-up is enabled by default, and catch-up runs after two missed scheduled scans.

  • Security Copilot · Windows
    Change Review Agent documentation now carries a deprecation notice

    The Security Copilot Change Review Agent overview now includes an agent-deprecation notice while its Intune admin center link remains unchanged. The supplied update gives no deprecation deadline or required administrator action.

  • Configuration Manager · Device security
    MBAM migration guidance adds PowerShell group retrieval and mapping

    Configuration Manager’s migration guidance now explains how to retrieve existing MBAM groups with PowerShell and map them to equivalent Configuration Manager BitLocker portal groups, allowing migrating administrators to reuse existing access groups.

For Intune administrators

Prepare administrators and internal runbooks for the September 2609 page change, and schedule large device-action batches within the documented daily quotas. Review Defender Antivirus policy values to confirm the intended catch-up behavior. Administrators using or referencing the Change Review Agent should review its deprecation notice; no deadline is supplied. MBAM migration teams can reuse existing groups when mapping them to Configuration Manager BitLocker portal groups.
