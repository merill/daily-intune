Day in brief

Intune guidance standardizes admin-center links and sign-in terminology, without behavior changes

22 June was overwhelmingly documentation maintenance: 487 recorded changes, including 486 updates, one removal, and no new items or Message Center notices. The supplied diffs repeatedly replace inline Microsoft Intune admin center URLs with a named reference link to `https://go.microsoft.com/fwlink/?linkid=2109431`, normalize “sign into” to “sign in to,” and normalize curly apostrophes. The representative examples preserve existing settings, paths, and behavior; they do not show a new capability, preview, general-availability change, retirement, deadline, or security-policy change.

  • Intune · Device configuration
    Settings Catalog Step 5 centralizes Edge policy links

    Intune’s Settings Catalog Step 5 moves repeated admin-center URLs into a named link reference. The listed Edge values remain `Default geolocation setting` = `Don't allow any site to track users' physical location (2)` and `Enable network prediction` = `Don't predict network actions on any network connection (2)`. Curly apostrophes were also normalized; no policy value or assignment behavior changes in the diff.

  • Intune · Device security
    Compliance Overview replaces the displayed truncated monitor link

    The Intune compliance Overview diff replaces the displayed `./monito…` reference for Monitor device compliance with `./monitor-policy.md`. It retains the route **Devices > Monitor > Setting compliance** and the setting name **Is active**, making this a documentation-navigation correction rather than a compliance-engine change.

  • Intune · App management
    Android MAM wording preserves Strict Tunnel Mode behavior

    The Intune MAM Android guidance still documents `com.microsoft.intune.mam.managedbrowser.StrictTunnelMode` with value `True`. It continues to state that Edge blocks internet traffic when an organization-account user is signed in and the VPN is disconnected, with browsing available again after reconnection; the supplied diff changes only “sign into” to “sign in to.” Existing MAM policies have no evidenced behavior change.

  • Windows Autopilot · Device enrollment
    Windows Autopilot Hybrid standardizes sign-in wording and links

    Windows Autopilot Hybrid guidance changes “Sign into” to “Sign in to” and converts admin-center URLs to named references. The documented navigation remains **Devices > By platform | Windows > Device onboarding | Enrollment > Windows Autopilot > Devices**; the diff shows no enrollment workflow or availability change.
