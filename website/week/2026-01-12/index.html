Week in brief

Hotpatch and expedited quality updates anchor Intune’s Windows servicing guidance

Windows servicing dominates the period: new Intune guidance details targeted expedited security updates and Hotpatch deployment through Windows Autopatch, while feature-update rollout guidance separates update availability from installation timing. Microsoft Edge for Business guidance was reorganized around enrolled versus non-enrolled devices, and Windows Autopilot now records a local-reset issue tied to a specific policy setting. Most remaining changes are prerequisite, terminology, navigation, or formatting maintenance.

  • Intune · Endpoint analytics
    Expedited Windows quality-update policies target one security update

    A new Intune policy guide describes accelerating a specific supported Windows security update while bypassing normal deferrals and deployment timing. It covers creation, assignment, monitoring, prerequisites, and eligibility; Windows versions earlier than 24H2 require Update Health Tools, and conflicting Group Policy settings should be removed before deployment.

  • Intune · Device updates
    Hotpatch guidance ties deployment to Autopatch and adds Arm64 conditions

    The new guidance explains how Windows Autopatch deploys Hotpatch security updates, including release cycles, reporting, and fallback to cumulative updates for ineligible devices. Eligible devices require VBS; Arm64 support is in public preview and additionally requires CHPE to be disabled and a restart.

  • Intune · Device updates
    Feature-update rollout guidance separates offer timing from installation controls

    Updated guidance now focuses on the three availability behaviors, offer groups, and rollout scheduling, while clarifying that installation timing depends on settings such as deadlines and restart controls. Administrators can use the distinction to plan gradual rollouts without conflating availability dates with installation timing.

  • Intune · App management
    Edge for Business policy paths now follow enrollment status

    The revised guidance assigns App Configuration Policies to non-enrolled devices and Settings Catalog policies to enrolled devices, warning against targeting both policy types to the same client. The corporate-data guide also removes its Security Baseline deployment step and says enrolled Windows devices should use either Settings Catalog policies or the Microsoft Edge Security Baseline, not both.

  • Windows Autopilot · Device enrollment
    Autopilot documents a reset failure caused by local network-denial policy

    A January 16 known-issue entry says local Windows administrators cannot initiate a local Windows Autopilot Reset when an Intune policy sets “Deny access to this computer from the network” for the Local account. The issue is under investigation; removing that setting is the documented workaround.

For Intune administrators

Before using expedited updates, verify Update Health Tools on Windows versions earlier than 24H2 and resolve conflicting update or Group Policy settings. For Hotpatch, Autopatch is required; configure VBS for eligible devices, and note that Arm64 support is in public preview and requires CHPE to be disabled plus a restart. Review Edge assignments for conflicting policy types, and remove the documented network-denial setting if local administrators must initiate a local Autopilot Reset. Use the rollout guidance to distinguish offer scheduling from deadlines and restart controls.
