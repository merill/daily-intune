Week in brief

Windows Autopilot policy conflicts can break hybrid-join pre-provisioning

The week’s clearest operational change is new Windows Autopilot failure guidance: Microsoft Entra hybrid-join pre-provisioning can fail when policy conflict resolution requires domain-controller connectivity and a bring-your-own VPN is unavailable during technician flow. Intune also expanded its in-development planning page, while Remote Help licensing and Advanced Analytics Device Query permissions received useful administrator guidance. The period was otherwise dominated by low-impact Configuration Manager metadata reclassification, with 870 of 884 changes categorized under Configuration Manager.

  • Windows Autopilot · Device enrollment
    Windows Autopilot documents a policy-conflict pre-provisioning failure condition

    The known-issues guidance says Windows Autopilot pre-provisioning for Microsoft Entra hybrid join can fail when policy conflict resolution requires domain-controller connectivity, particularly when a BYO VPN is unavailable during technician flow. It advises avoiding policies that require domain-controller connectivity during that flow.

  • Intune · General
    Intune’s in-development roadmap spans app protection, enrollment, and recovery

    The page adds upcoming MHS authentication for protected app activities, declarative VPP downloads, deployment plans, Defender launch during Android setup, bulk eSIM actions, new Apple settings, and Quick Machine Recovery policies. It also documents future macOS and iOS/iPadOS support changes and the September 2609 single-device page default.

  • Advanced Analytics · Endpoint analytics
    Device Query role guidance now emphasizes managed-device read permissions

    For multi-device queries, custom roles are documented as needing permissions to view and access managed devices, with Organization/Read and Managed devices/Read given as examples. The separate Managed Devices/Query permission is no longer listed.

  • Remote Help · Device enrollment
    Remote Help guidance says Android COSU Sharers need no license

    Supported Zebra and Samsung devices in Android Dedicated Device (COSU) mode don't require a Sharer license; only the Helper needs a Remote Help license. Administrators should reflect that distinction in licensing plans for supported deployments.

  • Intune · Compliance
    Intune’s servicing warning is now labeled Important

    The Servicing Information page changed its callout from Caution to Important. The accompanying message continues to cover impacts to updates, reliability, security mitigations, and feature enablement, and administrators are directed to consider communication with required Microsoft cloud services.

For Intune administrators

Review technician-flow policies that require domain-controller connectivity, particularly where a BYO VPN may be unavailable. Audit Device Query custom roles for managed-device view and access permissions, ensure Helpers are licensed for supported Android COSU Remote Help deployments, and use the Intune in-development page to plan for upcoming enrollment, app, platform, and recovery changes. Review the Important servicing note when assessing communication with required Microsoft cloud services.
