Day in brief

Network-denial policy blocks local Autopilot Reset; Intune clarifies Edge and update guidance

The clearest operational change is a newly documented Windows Autopilot known issue: an Intune policy that denies network access to the Local account prevents local Windows administrators from initiating a local Autopilot Reset. Other high-value edits sharpen how administrators target quality updates, choose Microsoft Edge policy paths, interpret Azure Monitor freshness, and satisfy RBAC prerequisites.

  • Windows Autopilot · Device enrollment
    Local Autopilot Reset is blocked by a specific network-denial setting

    The Windows Autopilot known-issues entry says that when an Intune policy sets “Deny access to this computer from the network” for the Local account, local Windows administrators cannot initiate a local Windows Autopilot Reset. The issue is under investigation; removing the setting is the documented workaround.

  • Intune · Device updates
    Quality Updates guidance separates update targeting from client behavior

    The guidance now describes targeting specific quality updates and states that restart settings, deadlines, notifications, and deferrals remain configured through update rings and Windows Update client policies. Use quality update policies for targeting or expediting, and the existing ring and client policy settings for client-side behavior.

  • Intune · App management
    Microsoft Edge policy paths are explicitly separated by enrollment status

    The Edge overview now states that App Configuration Policies and Settings Catalog policies targeting Microsoft Edge shouldn’t both be deployed to the same client because they can conflict. Non-enrolled devices use App Configuration Policies, while enrolled devices use Settings Catalog policies.

  • Intune · Endpoint analytics
    Azure Monitor guidance now gives precise report-delivery timings

    The documentation says Intune report data is sent to Azure Monitor once every 24 hours, may take up to an additional 24 hours to arrive, and typically appears within 30 minutes after Azure Monitor receives it. Use these timings when setting expectations for log availability and report freshness.

  • Intune · Device security
    Noncompliance email guidance now requires the Policy and Profile manager role

    The quickstart now lists an Intune subscription and the built-in Policy and Profile manager role as requirements, replacing the previous Intune Administrator guidance. It also removes the prior compliance-partner limitation; administrators following the guide should verify the revised role requirement.
