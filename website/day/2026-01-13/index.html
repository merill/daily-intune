Day in brief

Hotpatch guidance adds Autopatch deployment rules and Arm64 CHPE prerequisites

Intune’s 13 January material centers on Windows update administration. New guidance explains Hotpatch deployment through Windows Autopatch, fallback for ineligible devices, reporting, and Arm64 public-preview prerequisites. A separate Windows quality updates policy page documents expedited-update conflicts and pre-24H2 tooling requirements. Related updates sharpen driver approval governance, Hotpatch reporting, and Defender compliance workflows; many remaining edits are navigation, terminology, and link maintenance.

  • Intune · Device updates
    New Hotpatch guidance ties deployment to Autopatch and eligibility rules

    The new guide explains Hotpatch release cycles, reporting, prerequisites, and fallback to cumulative updates for ineligible devices. VBS is required for eligible devices; Autopatch is required for deployment. Arm64 support is identified as public preview and requires CHPE to be disabled and the device restarted.

  • Intune · Device updates
    Windows quality updates policy guidance defines expedited-update prerequisites

    The new policy page documents expedited security update deployment, release-date targeting, applicability, and conflicts with update rings and Group Policy. Update Health Tools are required on Windows versions earlier than 24H2.

  • Intune · Device updates
    Hotpatch reporting guidance adds a specific Intune admin-center path

    For policies with Hotpatch enabled, administrators are directed to Reports > Windows Autopatch > Windows quality updates > Reports to review deployment status, results, errors, targeted devices, and current update states.

  • Intune · Device updates
    Driver policy guidance formalizes ownership, rollout, and approval controls

    The revised guidance covers approval ownership, phased deployments, update cadence, automatic versus manual approval, approved-driver selection, Autopatch fallback, and pausing or reapproving drivers. Each device should be assigned to one policy, with updates explicitly approved when manual approval is used.

  • Intune · Device security
    Defender integration guidance reorganizes compliance and risk-based access setup

    The updated workflow emphasizes device compliance, real-time risk assessment, and automatic blocking of compromised devices. It presents a four-step integration process, adds a role-assignment tip, and reorganizes vulnerability-management and app-protection options.
