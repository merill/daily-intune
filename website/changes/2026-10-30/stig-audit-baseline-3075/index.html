Stig Audit Baseline

30 October 2026Feature updateAction required+23 / −32 lines

In brief

The STIG audit baseline is documented as available in commercial and GCC High environments. The update adds a View Reports role permission requirement, clarifies that audit-only profiles use Audit report, and updates initial reporting behavior and status meanings.

What Intune admins need to know

Ensure report viewers have Device configurations > View Reports permission. Expect initial results after 24 hours or longer, and interpret an early Error as potentially temporary data-retrieval failure rather than a failed check.

This summary was assembled from the tracked documentation change. Verify important details in the full Microsoft Learn article.

Device platform requirements

The Endpoint Security Manager built-in role includes these permissions. You can also add them to a custom role.

To view STIG audit reports, your Intune role must also include the Device configurations > View Reports permission.

You also need scope tag permissions for the device groups you want to audit.

Create a STIG audit baseline profile

  1. On the Assignments tab, select the device groups that you want to audit against the STIG baseline. You can target all devices or specific groups.
  2. Review your settings on the Review + create tab, and then select Create.

After you create the profile and assign it to groups, Intune evaluates the targeted devices against the STIG baseline as devices check in. Audit report data begins to populate as devices report their assessment results. Initial audit results for newly targeted devices can take up to 24 hours or longer to appear.

During initial reporting, devices may temporarily show Error before audit results become available. An initial Error doesn't necessarily mean the device failed a benchmark check. Error can also indicate a problem retrieving the data needed for evaluation.

Review STIG audit results

After devices check in, you can review audit results through the Audit report view in the Intune admin center.

Note

For audit-only baselines, including STIG, the profile overview doesn't show Device and user check-in status, Device assignment status, or the standard Per setting status report. Use Audit report to review per-setting audit results and drill down into individual device results.

  1. Go to Endpoint security > Security baselines, and select Microsoft Windows 11 STIG SCAP Benchmark.
  2. Select the audit profile you want to review.
  3. Select Audit report to load the report view. You might need to select Generate the first time to begin populating data.

Device assignment status

The Device assignment status report shows all devices that the policy targets, including devices in a pending policy assignment state. Use this report to confirm which devices received the audit profile and to track assignment progress.

Audit report

The Audit report shows whether device values meet the recommended values for settings in the baseline version. This report provides a per-setting summary across all targeted devices, so you can quickly identify which STIG rules have the highest failure rates and prioritize remediation efforts. Each row represents a single STIG rule and shows how many devices passed, failed, or reported other statuses for that rule.

Select the device count for a rule, such as the number under Success devices, to open a detailed view for that rule. The drill-down view includes:

Known limitations

  • Audit-only — The STIG Audit baseline doesn't enforce or fix settings. Use Settings Catalog profiles for configuration.
  • No custom baselines — You can't upload custom STIG profiles. The baseline includesevaluates the full set of STIG rulessupported automated checks for the supported benchmark. Rules requiring manual verification must be assessed separately.
  • No actual device values — The Audit report shows the pass or fail result of each rule check, but it doesn't display the actual configuration value on the device.
  • Single baseline version — You can only use the latest supported baseline version to create new Audit profiles. You can't create profiles against older baseline versions. However, profiles you previously created with an older version remain available to run.
  • GCC High onlyCloud availability — The STIG Auditaudit baseline isn'tis available in commercial, GCC, or DoD cloudcommercial and GCC High environments.
  • UX-only profile creation — You must create STIG Audit profiles through the Intune admin center. API-based profile creation isn't supported.
  • Data latency — Audit data isn't real-time. There can be a delay of several hours between a device evaluation and the data appearing in the report. For details, see Data freshness.
