Month in brief

Replace “Require approved client app” before June 2026 Conditional Access retirement

January’s clearest administrator deadline is the planned June 2026 retirement of the Microsoft Entra Conditional Access “Require approved client app” control; Microsoft directs organizations to “Require application protection policy” instead. A separate March change ends Microsoft Defender for Android protection of personal profiles on enrolled devices, while corporate work profiles and unenrolled devices remain unaffected. Beyond those notices, the supplied evidence is documentation-heavy but includes Configuration Manager’s MDT retirement, sharper Windows quality-update guidance, a 25-app Windows Autopilot device-preparation limit, and new Cloud PKI deployment material. The Cloud PKI additions describe cloud CA and BYOCA deployment models, CA creation, and audit procedures; they do not establish a separate January launch or general-availability announcement.

  • Intune · Compliance
    June retirement of the approved-client-app control

    Microsoft 365 Message Center says the Microsoft Entra Conditional Access “Require approved client app” control retires in June 2026. After retirement it will no longer be enforceable; the stated replacement is “Require application protection policy,” which provides equivalent and enhanced protection. This is a planned control retirement, not a documentation-only rename.

  • Intune · App management
    Defender for Android drops enrolled personal-profile protection

    By March 2026, Microsoft Defender for Android will stop protecting personal profiles on enrolled devices and focus on corporate work profiles. The notice says work profiles and unenrolled devices are unaffected and requires no administrator action. This is a change in protection scope and behavior.

  • Configuration Manager · Fundamentals
    MDT integration and standalone MDT are retired

    Configuration Manager release notes now state that MDT integration with Configuration Manager and MDT Standalone are no longer supported. Customers must remove all MDT task-sequence steps and then remove MDT integration to prevent task-sequence corruption and modification failures; Microsoft points to Windows Autopilot or supported operating-system deployment instead. This is a retirement with a concrete cleanup sequence.

  • Intune · Device updates
    Quality-update guidance limits expedited deployments

    New Intune guidance separates ordinary monthly quality updates, which continue to use Windows Update ring policies, from expedited deployment. Only eligible Windows security updates can currently be expedited; Windows versions earlier than 24H2 require Update Health Tools, and preview-build settings, non-default automatic-update behavior, notification suppression, and several Group Policy settings can interfere. This is operational prerequisite guidance, not evidence of a separate general-availability announcement.

  • Windows Autopilot · Device enrollment
    Autopilot device preparation limit rises to 25 apps

    The Windows Autopilot device preparation “What’s new” page records a limit increase to up to 25 apps in a device-preparation policy, applying to user-driven and automatic modes, including all Cloud PC offerings. The page dates the change January 30, 2026 and warns administrators to adjust deployment timeouts when configuring more apps.

For Intune administrators

Inventory Conditional Access policies using “Require approved client app” and replace that control with “Require application protection policy” before June 2026. No remediation is required for the announced Defender for Android scope change. Configuration Manager teams should remove MDT task-sequence steps before removing MDT integration. For Windows servicing, use update rings for ordinary monthly quality updates and validate the documented prerequisites before using expedited updates or Hotpatch. Revisit Autopilot device-preparation timeouts before assigning larger app sets. Cloud PKI planners should choose between a cloud root/issuing CA hierarchy and BYOCA, and verify the required CA-creation permissions.
