CMG security and privacy - Configuration Manager | Microsoft Learn

6 November 2026Feature update+13 / −8 lines

In brief

The documentation now states that shared-key access is automatically disabled for CMG storage starting in Configuration Manager version 2609, including existing deployments. It also adds required permissions for Microsoft Entra-authenticated storage and clarifies that storage keys and application secrets are separate credentials.

What Intune admins need to know

Review CMG server application and operator Azure RBAC permissions, particularly permissions to create the required Storage Blob Data Contributor and Storage Table Data Contributor role assignments.

This summary was assembled from the tracked documentation change. Verify important details in the full Microsoft Learn article.

For CMG deployments that use shared-key storage access on versions earlier than 2609, Configuration Manager rotates the storage account key for the CMG. This process happens automatically every 180 days. Starting in version 2609, shared-key access is automatically disabled for CMG storage, including existing deployments that previously used it. CMG storage operations use Microsoft Entra authentication instead. For the required Azure permissions and provider registration, see Configure Microsoft Entra ID for CMG.

Security mechanisms and protections

The service principals are authenticated by the server app registration in Microsoft Entra ID. This app is also known as the web app. You create this app registration automatically when you create the CMG, or manually by an Azure administrator in advance. For more information, see Manually register Microsoft Entra apps for the CMG.

The secret keys for the Azure apps are encrypted and stored in the Configuration Manager site database. As part of the setup process, the server app has Read Directory Data permission to the Microsoft Graph API. ItIts service principal also has the contributor roleneeds Contributor or equivalent resource-management permissions on the resource group that hosts the CMG. Each time the app needs to access resources like Microsoft Graph, it gets an access token from Azure, which it uses to access the cloud resource.

For Microsoft Entra-authenticated storage, the server application also needs permission to manage the required Storage Blob Data Contributor and Storage Table Data Contributor role assignments. Contributor alone doesn't grant permission to create role assignments. Use a Role Based Access Control Administrator assignment constrained to those two storage data roles at the CMG resource group, or equivalent approved permissions. Verify inherited access and any conditions before adding a new assignment. For details, see Configure Azure RBAC permissions for the server app.

The administrator who grants these permissions needs the appropriate Azure RBAC privileges at the target scope. Registering Microsoft.Maintenance separately requires provider-registration permission at the subscription scope. These operator permissions aren't the same as the runtime permissions granted to the CMG application. For details, see Configure Azure resource providers.

Disabling shared-key access to the storage account doesn't remove the server application's client-secret requirement. Storage account keys and Microsoft Entra application secrets are different credentials.

Microsoft Entra ID can automatically rotate the secret key for these apps, or you can do it manually. When the secret key changes, you need to renew the secret key in Configuration Manager.
