Day in brief

Endpoint Privilege Management now enforces scope tags on elevation requests

April 7 was a high-volume documentation day: 327 records included 290 updates, 19 new pages, and 18 removals. Most representative edits were mechanical path and cross-reference repairs across Autopilot, endpoint security, RBAC, Configuration Manager, and certificate content. The substantive exceptions were enforced EPM scoping and new certificate-management guidance for derived credentials and S/MIME.

  • Endpoint Privilege Management · Device security
    EPM elevation requests are now constrained by scope tags

    The Intune What's New entry says applicable scope tags are now enforced when administrators view Endpoint Privilege Management elevation requests. Administrators can view and manage only requests for devices and users within their assigned scope, strengthening administrative boundaries.

  • Intune · Device security
    Derived-credential setup is documented with a one-issuer tenant limit

    A new Intune how-to explains configuring a supported third-party derived-credential issuer and selecting Derived credential for Android Enterprise fully managed, iOS/iPadOS, and Windows authentication scenarios. Only one issuer can be used per tenant, and a trusted root certificate is required. Windows VPN authentication with derived credentials is currently not working as expected, with no ETA for the fix.

  • Intune · Device security
    New S/MIME guidance details certificate delivery across mail clients

    The new Intune article covers S/MIME certificates for Android, iOS/iPadOS, and Windows. Intune automatically delivers certificates and associates them with native iOS mail and Outlook on iOS and Android; users must manually enable S/MIME in Windows, macOS, and other mail clients. Signing certificates use PKCS and require the Certificate Connector for Microsoft Intune.
